# Proxy App 架构说明

## 概述

Proxy App 是一个基于 NestJS 的代理工具，提供可视化的界面来管理和配置 HTTP 代理。

## 架构设计

### 端口分离设计

```
┌─────────────────────────────────────────────────────────┐
│                    用户浏览器                             │
└─────────────────────────────────────────────────────────┘
                           │
         ┌─────────────────┴─────────────────┐
         │                                   │
   访问 http://localhost:3000        访问 http://localhost:57475/api/xxx
         │                                   │
         ▼                                   ▼
┌─────────────────────┐         ┌─────────────────────────┐
│   主服务 (3000)     │         │  代理服务 (57475)       │
├─────────────────────┤         ├─────────────────────────┤
│  /project/* → API  │         │  所有请求 → 转发到目标  │
│  /* → 前端静态文件 │         │  地址                   │
└─────────────────────┘         └─────────────────────────┘
```

### 代理服务（项目独立端口）

**文件位置**: [proxy.service.ts](file:///d:/study/react/proxy-app/proxy-backend/src/proxy/proxy.service.ts)

每个项目启动时会创建独立的代理服务器，监听配置的端口：

- 所有到达该端口的请求都会被转发到目标地址
- 支持自定义请求头（从项目配置读取）
- 支持二进制资源（图片、音视频、PDF）的流式传输
- 支持 WebSocket 和透传接口

## 代理功能特性

### 1. 自定义请求头转发

从项目配置的 `configs[0].headers` 读取自定义请求头，在转发时注入到请求中。

### 2. 透传接口支持

自动识别以下路径，采用直通模式，不做任何修改：
- `/ws`
- `/socket.io`
- `/stream`

### 3. 二进制资源处理

自动识别以下 Content-Type，采用流式传输：
- `image/*`
- `video/*`
- `audio/*`
- `application/octet-stream`
- `application/pdf`

### 4. 响应数据处理

区分文本和二进制内容，支持响应拦截和修改。

## 项目数据结构

**文件位置**: [storage.service.ts](file:///d:/study/react/proxy-app/proxy-backend/src/storage/storage.service.ts#L6-L19)

```typescript
interface Project {
  id: number;
  name: string;
  config: string;
  address: string;  // 本地代理地址
  destination: string;  // 目标服务器地址
  status: 'running' | 'stopped' | 'reloading';
  description: string;
  port: number;  // 本地监听端口
  configs: Array<{
    targetAddress: string;
    headers?: Record<string, string>;  // 自定义请求头
  }>;
}
```

## 工作流程

### 启动代理流程

1. 用户在前端界面创建/编辑项目
2. 配置目标地址、端口、自定义请求头等
3. 点击「启动」按钮，调用 `/project/action/start`
4. 后端创建独立的代理服务器，监听配置的端口
5. 用户可通过 `http://localhost:{端口}` 访问被代理的服务

### 请求转发流程

1. 用户请求 `http://localhost:{代理端口}/api/xxx`
2. 代理服务接收请求
3. 注入自定义请求头
4. 转发到目标地址
5. 接收响应并处理（区分文本/二进制）
6. 返回响应给客户端
